# MCP карт BandaStation

`bandastation-maps` предоставляет координатное чтение, изображения, адресные изменения и проверки существующих TGM-карт `.dmm`, включая несколько Z. Raw DM-выражения сохраняются текстом; сервер их не исполняет.

## Установка и проверка

Из корня checkout:

```powershell
tools/agents/setup-maps.ps1
node tools/agents/mcp/maps-mcp.cjs --check
node tools/agents/tests/test-maps-mcp.cjs
```

Установщик закрепляет SDK 1.29.0 и Windows `dmm-tools` suite-1.12, проверяет SHA256 renderer и `icon-smoothing-2025`. Runtime: `%LOCALAPPDATA%/BandaStation/agent-tools/maps/`. Вызовы MCP ничего не скачивают. Python берётся из проектного bootstrap cache; если он ещё не подготовлен, выполните `tools/bootstrap/python.bat -c "import bidict, PIL, yaml"`.

Setup обновляет только `[mcp_servers.bandastation-maps]` в локальном `.codex/config.toml`, сохраняя другие таблицы. `-ConfigOnly` не ставит зависимости. Глобальная конфигурация, Git hooks/excludes и игровые версии не меняются. Standalone smoke и доступность инструментов именно в открытом чате проверяются отдельно. После установки при необходимости переоткройте проект/подключение MCP и проверьте список tools.

## Инструменты

| Имя | Результат |
| --- | --- |
| `dmm_capabilities` | Версии, готовность renderer и ограничения. |
| `dmm_info` | Размеры, hash, области и сводка типов. |
| `dmm_read` | Клетки и упорядоченные raw atoms с индексами. |
| `dmm_find` | Exact typepath либо лексический prefix; `parent_type` не разрешается. |
| `dmm_render` | PNG со спрайтами или схемой, координатами и масштабом. |
| `dmm_prepare_patch` | Кандидат, snapshot исходника и diff без изменения карты. |
| `dmm_apply_patch` | Атомарное применение актуального подготовленного плана. |
| `dmm_diff` | Изменения клеток/atoms независимо от dictionary keys. |
| `dmm_validate` | Структура и штатный YAML maplint. |

Пути задаются явно внутри checkout; traversal, symlink/junction и служебные каталоги запрещены. Формат DMM не преобразуется автоматически в TGM. Неподдержанный синтаксис вызывает диагностику.

Координаты — BYOND `[x,y,z]`, от 1, Y на север. Границы регионов включительны. `atom_index` — от 0 по полному исходному стеку, включая turf/area. Поиск/чтение возвращают `truncated` и `next_cursor`, связанный с запросом и hash.

Источник — `{"path":"_maps/shuttles/ss220/argos_basic.dmm"}` либо `{"plan_id":"...","side":"before"}` / `after`. Например, аргументы `dmm_read`:

```json
{"source":{"path":"_maps/shuttles/ss220/argos_basic.dmm"},"coordinates":[[2,16,1],[3,16,1]]}
```

## Цикл правки

1. Прочитать `dmm_info` и нужные клетки; сохранить актуальный `sha256` и raw atoms.
2. Посмотреть общий вид и детали. Использовать названный референс либо стиль исходной карты и соседних помещений.
3. Подготовить `dmm_prepare_patch` с `path`, `expected_sha256` и `operations`.
4. Посмотреть `sources.after` из ответа через `dmm_render` и проверить `dmm_diff` в тех же координатах/масштабе.
5. Применить выбранный `plan_id`, выполнить `dmm_validate` и относящиеся игровые проверки.

Пример операции:

```json
{"op":"replace_atom","at":[12,8,1],"atom_index":0,"expected_atom":"/obj/item/crowbar","atom":"/obj/item/screwdriver"}
```

Поддерживаются `add_atom`, `remove_atom`, `replace_atom`, `set_turf`, `set_area`, `set_tile`, `fill_region`, `copy_region`; точные поля доступны в schema. Все операции адресуют один исходный snapshot, включая перекрывающееся copy. Конфликты отклоняются целиком. Поворота фрагментов нет. Vars меняются заменой полного raw atom.

Правка клетки общего key не меняет остальные occurrences. Незатронутые байты/комментарии/определения сохраняются, новые keys детерминированы. При исчерпании ключей запись отклоняется. No-op и повторное apply не переписывают карту. Перед apply проверяются snapshots, операции, исходный hash и актуальный maplint. Apply сериализован внутри одного сервера; внешние редакторы межпроцессной блокировкой не охватываются.

Планы и PNG остаются в `task_state/map-tools/`. Prepare/apply — последовательность самого агента; каждую уже разрешённую правку не требуется повторно согласовывать с пользователем.

## Визуальный результат

Виды: `appearance`, `power`, `atmos`, `areas` (цветовая схема областей). До 8 изображений, контекст 0..8 клеток, scale 1/2/4, preview 64..2048 px. Native budget 67108864 пикселя; большие карты смотрят по Z/участкам. Полные PNG сохраняются. Одинаковые виды группируются в `render-many`; разные presets требуют отдельных native процессов.

После правок проверяйте общий силуэт, проходы, двери, плотность оборудования, материалы/цвета, повторяемость деталей и примыкания. Отдельно смотрите сети и области. Диагностика и actual passes возвращаются вместе с изображением; random substitutions отключены. Прозрачный network-view может означать отсутствие сети.

## Границы проверки

Для runtime-иконок применяется временный `.maps-preview-*.test.dme` в корне checkout, удаляемый после рендера. Он включает исходное окружение и существующие renderer smoothing overrides. Для семи текущих семейств диагональных стен сохраняются локальные DMI-копии с совместимыми именами состояний: исходные pixel chunks и игровые ресурсы остаются неизменными. Эти адаптации отражаются в metadata. Динамические overlays отдельных механизмов могут отличаться; соответствующие native diagnostics сохраняются.

Maplint использует исходный логический путь; baseline-ошибки отделяются от новых. Недоступный lint и новые нарушения блокируют реальную правку. Лексическая сохранность не доказывает смысл произвольных DM-выражений.

Статический PNG/maplint не исполняет `Initialize()` и не доказывает питание, герметичность, работу механизмов или полёт. Для задачи проследите template → JSON/includes → DM-контракт и выполните соответствующий build/test/игровой сценарий штатными средствами проекта.

Проверки Python: `tools/bootstrap/.cache/python-<version>/python.exe -B -X utf8 -m unittest discover -s tools/agents/tests -p test_map_*.py -v`. Cache определяется `dependencies.sh`/`TG_BOOTSTRAP_CACHE`. Атомарная замена тестовых файлов в этой Windows sandbox может требовать штатного `require_escalated`.
