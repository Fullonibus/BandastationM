# Argos M

Отдельная overmap-версия на основе `_maps/shuttles/ss220/argos_basic.dmm`. Обычный служебный Argos сохраняется. Пользователь выбрал корпус 12×22 с новым кормовым техническим отсеком и сохранением существующих помещений.

Общий [чек-лист корабля](../space_overmap/MAPPING_CHECKLIST.md) основан на текущих кодовых контрактах. Новая карта — [`_maps/map_files/overmap_ships/argos.dmm`](../../_maps/map_files/overmap_ships/argos.dmm), определения — [`code/argos.dm`](code/argos.dm).

## Исходный аудит

Координаты исходной карты: BYOND XYZ, Z=1. Размер **12×17×1**, 204 клетки; 202 клетки `/area/shuttle/argos`, две `/area/template_noop`. SHA256 `c94b5ede96ec9086fc07acf50f8307d8c85443415ac04f630348426f5a561125`. Чтение/инвентаризация/maplint выполнены через `bandastation-maps`; maplint исходника PASS.

## Выполненная модернизация

Добавлены 5 рядов между исходными y=1 и y=2: прежние y≥2 смещены на +5, кормовой обычный выход остаётся на y=1. Корпус **12×22×1** помещается в стандартный **M 19×25**. Единственный overmap mobile в `(6,1)` имеет `shuttle_id = "overmap_argos"`, `ship_class = "medium"` и собственный корень area. Бар, салон, медотсек, изолятор, EVA, рубка, каюта и исходный инвентарь сохранены. Растение со столом в рубке перенесены с `(4,21)` на `(2,20)` ради третьей консоли.

Все координаты далее относятся к новой карте, Z=1.

## Загрузка

Запустить существующий профиль **Cyberiad Overmap**, затем **Events → Load/Jump Lazy Template → Overmap — argos**. Меню использует текущий loader: повторный выбор возвращает уже загруженный живой экземпляр. Стартовый fleet и `starting_dock` не заданы; новую карту не нужно включать в старый shuttle template. Профили Trurl, CentCom и обычный Argos этой модернизацией не меняются.

## Проверка

- PASS: установленный maps MCP — prepare, appearance/power/atmos/areas, apply, maplint без ошибок. Оригинальный SHA256 сохранён. Сравнение фактических клеток подтвердило сохранение всех исходных объектов, кроме трёх заменённых старых controls/mobile.
- PASS: независимый статический обход границ обеих техкомнат, доступность оборудования и hatch cells; наложения новых настенных панелей на исходные лампы устранены.
- PASS BYOND: CI compile 0 ошибок; 5/5 целевых engine test statuses успешны — реальный DMM/production template, bindings, M acceptance/hatches, powernets/APC и передача газа, доступ к трём пресетам и действие транспондера, две регрессии blackout, общий M-controller dock/depart. `clean_run.lk = Success!`, штатное завершение. DreamDaemon вернул 176, поэтому общий `dm-test` target не обозначается как PASS.
- PASS реальный Argos: native M docking, открытие обоих endpoints, отстыковка и возврат на flight berth. Отдельный локальный сценарий за 489.663 s выполнил два штатных четырёхминутных перехода: заряд 2 → 1 → 0, третий переход отклонён. После возвращения все 9 powered areas сохранили оборудование под питанием, все внутренние floor-клетки — давление 70..140 kPa и температуру 260..330 K. Два финальных engine test statuses успешны, runtime-ошибок 0, `clean_run.lk = Success!`. Windows DreamDaemon завершился с кодом 96; этот ненулевой код обёртки сохраняется в отчёте отдельно от успешных игровых проверок.
- Временные include/focus/диагностика удалены. Восемь минут ожидания переходов остаются локальной приёмкой; постоянный интеграционный тест содержит короткий сценарий загрузки, сетей и M docking/depart.
- PASS окончательной компиляции: `tools/build/build.bat dm --skip-icon-cutter -DCIBUILDING` — 0 ошибок, 2 ожидаемых CI-предупреждения; `tools/build/build.bat dm` — **0 ошибок, 0 предупреждений**, exit 0. Обычная игровая сборка оставлена без CI-флагов.

Условия M-причала: герметичный принимающий отсек с пригодной атмосферой и запасом воздуха для трапа. Приёмка использует три станционных клетки (doorway + две внутренние), штатный воздух перед стыковкой; воздух Argos не подменяется. Двухклеточная невентилируемая камера выявила ограничение существующего общего equalizer: после заполнения трапа локальные давления расходятся и открытие блокируется. Общая механика трапов в этой модернизации не изменена.

Дополнительные ручные проверки: загрузка через меню в обычном раунде, живой радиообмен и scan, пилотирование/торможение из интерфейса, проход экипажа по трапу и выход после реальной посадки, длительная работа под нагрузкой экипажа. Интеграционный тест проверяет механизмы напрямую; звук генераторов изолирован от сетевой приёмки, клиентское аудио этим тестом не проверяется.
